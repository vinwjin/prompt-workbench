# 维护、PR与发布

每周集中分类Issue/PR，每月核查Node支持、Actions版本、安全报告及来源条款。数据变化做恢复演练；每季度复核权限/令牌及维护范围。响应目标不等于值守保证。

PR：一个问题一个分支，先审Files changed再隔离运行；需求/规范分别检查，尤其凭据、生命周期、数据、来源、费用和CI权限。新提交重新检查，人工squash merge，不自动发布。单人维护不要求自己Approve自己；有第二位可信维护者后再启审批人数。

main：要求PR、必需检查、解决审查讨论，禁止强推/删除。关键路径列CODEOWNERS。紧急旁路必须留下原因与后补审查。陌生PR禁运行于日常自托管runner；不用pull_request_target检出陌生代码。Actions固定完整SHA，权限最小化。

Release：固定精确提交→检查/测试/隔离UI→白名单和秘密扫描→源码包manifest/哈希→解压另一目录空数据启动→草稿预发布→维护者确认→发布→公开下载核验。已发布tag不移动，同版本附件不替换。签名/安装器/自动更新尚未实现。

GitHub开启私密漏洞报告、推送密钥保护及可用的静态扫描。Actions依赖更新PR人工审查。CI不得存真实模型API key，健康检查不发提示词。源码包只含git跟踪的批准文件，不复制整个工作目录。

事故：密钥泄漏先吊销/轮换，停止受影响流程；数据损坏先停写/保留故障副本；恶意供应链暂停发布并核对哈希；来源失效保留缓存与私人收藏，禁自动重试生成。确认影响后提供修复版本与公开说明，不删除私人记录。

暂停维护时标明支持终止及最后可用版本，必要时归档；任何账号/仓库权限变更由维护者明确执行。
