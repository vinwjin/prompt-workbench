# 数据、升级与恢复

正式数据为data/workbench.sqlite和data/media；备份/日志/图片缓存亦在data。提示词、素材、备份并非全盘加密；Windows DPAPI仅密钥。

升级前正常关闭应用、确认模型状态，复制完整data到本机安全位置。不要在写入时只复制SQLite主文件遗漏WAL。新程序放独立目录，先用备份副本测试。PW_DATA_DIR可指向数据目录，PW_PORT可指定端口；启动/关闭用相同环境变量。

业务JSON不含可用密钥；合并恢复不覆盖现有ID，不是覆盖回滚。完整导出含素材时有体积限制，附件很多则分批或复制完整data。自动JSON备份含素材关联而非所有媒体字节，单拷JSON可能不足。跨Windows用户/电脑密钥需重填，原密文不可用。

代码回退不等于数据回退：旧软件拒绝更高schema，必须恢复升级前一致快照；先保留后来新增内容，说明回退可能损失快照后记录。迁移失败不删原库。

自动JSON备份保留最近20份，缓存默认512MB/30天；不可变私人附件为保证恢复会长期保留，日志未自动轮转。不要手动删有备份引用的附件；需要清理先备份并确认影响。


## 0.4.2 数据中心与升级

分类容量只按需统计，不执行清理、压缩或自动维护。“数据库快照”使用SQLite一致性备份，最多保留3份，满额拒绝而不自动删旧文件；快照包含数据库中的加密凭据／公共记录，但不包含data/media中的素材，不能代替完整data备份。快照跨Windows用户不能直接解密凭据，账号需重新登录。

升级前保存草稿、正常关闭旧后台，复制完整data到安全位置，再解压新程序到独立可写目录并迁入data；不要用空数据覆盖原data。新版页面遇到旧后台提供兼容草稿保存／正常退出入口，其他功能待原启动器重开新版。回退前先保存现有数据副本，再使用原程序及对应data备份；不要把旧快照直接覆盖升级后的新增内容。
